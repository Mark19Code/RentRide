# RentRide (RR)

**Your Ride. Your Journey. Your Way.**

RentRide is a Django-based car rental and fleet operations application built as a local college project. It includes fictional sample fleet data, a rental workflow, customer records, payments, maintenance, reports, and a simulated Metro Manila GPS view. It does not connect to physical GPS devices or payment gateways.

## Features

- Database-backed dashboard metrics and revenue trend.
- Vehicle inventory with search, filters, specification details, images, and availability state.
- Customer profiles, rental history, and license validation.
- Rental reservations with overlap validation, duration/fee calculation, and vehicle status synchronization.
- Simulated payment records and balance/status updates.
- Maintenance scheduling and vehicle service status.
- GPS demo map using Leaflet/OpenStreetMap when online and a local marker fallback when offline.
- GPS simulation updates coordinates, speed, location labels, timestamps, and GPS history.
- Rental history filters and CSV export; fleet and revenue reports.
- Django authentication, CSRF-protected forms, password/profile settings, and Django admin.
- `seed_data` creates 154 fictional vehicles, 35 fictional customers, 60 rentals, payment records, GPS history, maintenance records, and a development admin account.

## Technology

- Python 3.10+ (tested with Python 3.13)
- Django 5.2 LTS
- SQLite (`db.sqlite3`)
- Pillow for optional uploaded vehicle images
- Django Templates, HTML, CSS, and vanilla JavaScript

## Windows setup (PowerShell)

From the folder containing `manage.py`:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py makemigrations rental
python manage.py migrate
python manage.py seed_data
python manage.py runserver
```

Open <http://127.0.0.1:8000/>. For Command Prompt, activate with `\.venv\Scripts\activate.bat` instead.

The project also works with the existing `.venv` if one is already active. The seed command is safe to rerun: existing generated IDs are retained and only missing records are added.

## GPS and payments are demonstrations

GPS points are fictional coordinates around Metro Manila. Choose **Simulate GPS update** to generate new points and append GPS history; no hardware, location permissions, or paid map credentials are used. The page labels all readings as simulation/demo mode. OpenStreetMap tile loading requires an internet connection; the map area still shows a local fallback visualization without it.

Payment entries only record sample amounts and methods in SQLite. No card, bank, GCash, or Maya transaction is initiated.

## Troubleshooting

- **`No module named django`:** activate `.venv`, then run `python -m pip install -r requirements.txt`.
- **`can't open file manage.py`:** change to the project root (`D:\RentRide`) before running commands.
- **No demo records:** run `python manage.py migrate` followed by `python manage.py seed_data`.
- **Map tiles are blank:** confirm internet connectivity. The simulated coordinates and fallback map markers remain available locally.
- **Image upload fails:** install Pillow from `requirements.txt`; uploaded files are stored under `media/cars/`.
- **Demo credentials do not work:** the seed command does not reset passwords for an existing `admin` account. Use Django admin or `python manage.py changepassword admin` to set one.

## Security note

The settings include a development-only fallback secret key. Set `DJANGO_SECRET_KEY` and `DJANGO_DEBUG=0` for deployment, configure `DJANGO_ALLOWED_HOSTS`, and never deploy with the demo account/password or development configuration.

## Publish online with Render

The local development server at `127.0.0.1` is private to the computer running it. To let people on other devices and networks reach RentRide, deploy it to a public hosting provider. This repository includes `render.yaml` as a Render blueprint for a demo deployment with a PostgreSQL database, HTTPS, and production static-file serving.

1. Create/sign into a GitHub account and create a **private** repository for RentRide. Do not commit `.venv`, secrets, database files, or real customer records. Push this project to that repository.
2. Create/sign into Render, select **New → Blueprint**, and connect the RentRide GitHub repository. Review the blueprint services and choose **Apply**. It provisions the web service and PostgreSQL database; the first build/deploy takes several minutes.
3. When Render reports the web service as **Live**, open its `https://...onrender.com` URL. Anyone with that URL can reach the login page; only users with accounts can access the management app.
4. During Blueprint setup, enter a **new, unique password** in each of the three `DJANGO_ADMIN_*_PASSWORD` secret fields. Do not reuse any local account passwords; credentials have been disclosed in development chat and must be considered compromised. The startup bootstrap creates `ampal`, `mandadero`, and `buenaventura` as superusers in the hosted PostgreSQL database. The local SQLite users and passwords do not transfer. After the first successful deployment, remove the three password variables from Render's Environment settings; the created accounts remain in PostgreSQL and the bootstrap command won't reset existing account passwords.

The blueprint uses its own persistent PostgreSQL database and runs migrations plus idempotent sample-data seeding at startup. It skips the well-known `admin / Admin@12345` demo user. Render's free instances may sleep while idle and free database plans have provider-specific limits/expiration; check Render's current terms. Uploaded images use local media storage, which is ephemeral on free web instances—avoid relying on uploaded files for a hosted demo unless you add persistent/object storage. Local media files and SQLite data are not uploaded by Git.

For a class presentation, keep the source repository private, use newly generated account passwords, and share only the deployed HTTPS URL with your colleagues. A host account/repository connection and deployment approval are required; this workspace cannot publish a public URL without those accounts and access.
